# SASE Private Access Policy Sync

## Overview

SASE Private Access Policy Sync is a SmartConsole extension backend that automates synchronization of Check Point Access Policies to Check Point SASE.

### Key Features

* Fetch rulebases from a centralized Check Point Management Server
* Map Check Point rules to Check Point SASE format
* Validate policies before deployment
* Push policies to selected SASE networks

---

# Architecture

* **SmartConsole** → Loads extension UI and triggers actions
* **Backend Service** → Processes rulebase and communicates with APIs
* **Check Point Management Server** → Source of rulebase data
* **Check Point SASE** → Target system for policy deployment

---

# Requirements

## System Requirements

* Linux server (Ubuntu recommended)
* Python 3.10+ with the `venv` and `pip` modules available (Ubuntu/Debian: `sudo apt install python3-venv python3-pip`)
* Access to Check Point Management API
* Check Point SASE API credentials
* Run as a regular (non-root) user with `sudo` privileges — do **not** log in as `root` and run the scripts directly, this has caused setup/run failures. Use `sudo` from a normal account instead.
  (Reason: `setup.sh` detects the invoking user via `$SUDO_USER`, which `sudo` sets but a direct `root` login doesn't, so the systemd service ends up misconfigured.)

## Connectivity Requirements

The backend must be reachable from:

* SmartConsole client
* Check Point Management Server

Required endpoint:

```text id="xq9m0v"
https://<SERVER>:5000
```

Used for:

* Loading SmartConsole extension (`extension.json`)
* Backend API communication (validate/install)
* UI interaction from SmartConsole

# Installation

## 1. Clone Repository

```bash id="c8q2lm"
git clone https://github.com/OrgCPLabSwitzerland/sase-private-access-policy-sync
cd sase-private-access-policy-sync
```

## 2. Run Setup (Recommended)

> ⚠️ Run this as a regular user with `sudo` privileges, not while logged in directly as `root` — running as `root` has been known to cause failures.

The setup script prepares everything automatically and walks you through each step:

```bash id="s3n9aa"
sudo ./setup.sh
```

What it does:

* Creates the Python virtual environment and installs dependencies
* Interactively prompts for your SASE API key, Management server IP/hostname, and Management API key, then writes `config/config.json` (if missing)
* Interactively prompts for the backend's IP/hostname and generates `frontend/extension.json` from the template (if missing)
* Generates a self-signed TLS certificate (`certs/cert.pem` / `certs/key.pem`) matching the backend's IP/hostname
* Optionally installs and starts a systemd service (`sase-private-access.service`) to auto-start the backend on boot, with `Restart=always`

The script pauses after each stage so you can review the output before continuing.

---

## 3. Start Backend

If you installed the systemd service during setup, the backend is already running and will auto-start on boot — no further action needed.

To run it manually instead (e.g. for testing, or if you skipped the systemd service):

```bash id="z2m8kd"
./start.sh
```

---

# Post-Setup Configuration

## Config File

`config/config.json` is created by `setup.sh` from the values you enter interactively (SASE API key, Management server IP/hostname, Management API key). It's gitignored and never committed.

If you need to change anything afterwards (e.g. the SASE auth/base URLs, or `VERIFY_TLS`), edit the file directly:

```text id="c9x2aa"
config/config.json
```

---

## Extension Configuration

`frontend/extension.json` is generated by `setup.sh` from the backend IP/hostname you provide. If you need to change the backend address afterwards, edit this file directly:

```text id="e8k3lp"
frontend/extension.json
```

and replace the host in:

```text
https://<YOUR-SERVER>:5000
```

---

# SmartConsole Extension Setup

## Register Extension

1. Open SmartConsole
2. Navigate to:

   ```
   Manage & Settings → Extensions
   ```
3. Click:

   ```
   Add → From URL
   ```
4. Enter:

   ```
   https://<SERVER>:5000/extension.json
   ```
5. Click **Add**

---

## Result

A new tab will appear:

**Install SASE Policy**

Located in the Access Policy section.

# Troubleshooting

## Extension Not Loading

Check:

```text id="t4q1zz"
https://<SERVER>:5000/extension.json
```

## Backend Issues

* Check backend logs
* Ensure port `5000` is open
* Ensure server is reachable from SmartConsole

## Certificate Issues

If using self-signed certificates:

* SmartConsole must trust the certificate
* HTTPS must be correctly configured

# Cleanup

To remove everything `setup.sh` created (systemd service, virtual environment, and optionally `config/config.json`, `frontend/extension.json`, and the TLS certificate):

```bash id="cln9aa"
chmod +x cleanup.sh
./cleanup.sh
```

It stops/disables/removes the systemd service and deletes `venv/` automatically, then prompts before deleting each file that may contain credentials or a valid certificate.

---

# Notes

* The backend does **not** run on the Management Server
* SmartConsole communicates directly with backend via HTTPS
* `setup.sh` handles environment initialization, credential configuration, and systemd service installation automatically
* `cleanup.sh` reverses everything `setup.sh` created
